## 4. Решение для лабы 3: алгоритм методички и TextRank

Пользователь уточнил, что OSTIS необязателен. Прежнее ожидание уточнений снято.
Выбранный план — локальная реализация двух объяснимых режимов реферирования.
Это решение задачи лабораторной, а не эквивалент всей платформы OSTIS.

Основной режим:
- spaCy en/es: предложения, токены, леммы; сохранить абзацы и исходные позиции.
- TF-IDF и позиционные веса точно по формулам методички; формулы PDF предварительно
  просмотреть визуально, не заменять автоматически стандартной формулой sklearn.
- IDF рассчитывать по документам корпуса соответствующего языка.
- Отобрать K предложений и восстановить исходную последовательность.
- Вывести ключевые слова с TF-IDF-весами отдельным разделом.

Сравнительный режим TextRank:
- Вершины графа — предложения, веса рёбер — лексическое сходство.
- Использовать пересечение нормализованных слов с нормировкой по длинам предложений,
  основанное на статье TextRank; правила лемматизации и стоп-слов описать явно.
- Рассчитать взвешенный PageRank через NetworkX, начальный alpha=0.85.
- Исключить петли и нулевые рёбра; отобрать K предложений по рангу,
  затем восстановить исходный порядок. При равенстве рангов — исходный индекс.
- Общие ключевые слова оставить на TF-IDF, второй граф для слов пока не нужен.
- Не выдавать лексическое сходство за полноценный семантический анализ.
- Обработать пустой текст, одно предложение, пустой словарь, нулевые связи.
  Для отсутствия связей предусмотреть позиционный резервный выбор с явным
  уведомлением в результате и отчёте. Несходимость PageRank диагностировать отдельно.
- Вернуть не больше имеющихся предложений; исходные предложения не переписывать.

Интерфейс и демонстрация:
- Исходник, классический реферат, список ключевых слов, ссылка на документ.
- Выбор метода: «TF-IDF + позиционные веса» или «TextRank».
- Настраиваемый K, по умолчанию 10.
- Таблица предложений: номер, оценка, признак отбора.
- Одинаковые документы и K при сравнении двух методов.
- Время предобработки и ранжирования; загрузку модели учитывать отдельно.
- Степень сжатия по словам/предложениям; экспертная оценка информативности,
  связности и повторов отдельно по двум языкам и двум предметным областям.
- Согласие алгоритмов не считать точностью; превосходство TextRank не обещать.
- При наличии эталонных рефератов позднее можно добавить ROUGE; сейчас он не требуется.
- Сохранение, печать и справка обязательны. Визуализация графа — возможное улучшение,
  отдельный обязательный экран для неё не нужен.

Архитектура:
- Два компонента ранжирования за небольшим общим контрактом.
- Один сервис сборки результата, общие предобработка, ключевые слова и экспорт.
- Результат содержит метод, параметры, оценки, индексы выбранных предложений,
  ключевые слова, время и диагностические сообщения.
- Protocol и композиция без лишней иерархии классов.
- spaCy en_core_web_sm/es_core_news_sm, numpy/scipy, NetworkX.
- scikit-learn из лабы 2 можно переиспользовать при необходимости;
  формулы основного алгоритма реализовать явно.
- Всё работает локально после установки зависимостей и языковых моделей.
- OSTIS/sc-machine/py-sc-client и отдельный сервер не нужны.

Проверки: порядок, K, воспроизводимость, ручные примеры весов, граничные входы,
оба языка и обе области, экспорт, ссылки, корректное измерение времени.
