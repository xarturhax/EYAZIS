# Лабораторная №1 — информационный поиск, вариант 36

Вариант: отбор документов из Интернета, вероятностное ранжирование,
английские тексты и запросы. Интерфейс и пояснения — на русском.

Система загружает страницы, сохраняет текст и инвертированный индекс в SQLite,
ранжирует документы по BM25 и оценивает поиск по экспертной разметке.

## Запуск

Из корня проекта:

```powershell
.venv\Scripts\python.exe -B -m lab1
```

Откроется страница №1 общего веб-приложения. Также работают `lab1/main.py`
из PyCharm и `start_web.cmd` для главной страницы всех лабораторных.
Подготовка зависимостей и сборки: [webapp/README.md](../webapp/README.md).
Окружение на текущем компьютере уже подготовлено. Старый оконный интерфейс удалён.

## Работа в браузере

1. **Поиск → Загрузить демо-коллекцию**: 12 коротких английских текстов и оценки
   пяти запросов. Тексты авторские, ссылки ведут к тематическим источникам;
   это не скачанные копии соответствующих сайтов.
2. Введите `python programming`, нажмите **Найти**. Результаты показывают заголовок,
   URL, начало текста, совпавшие слова и балл BM25.
3. Нажмите заголовок для полного текста и ключевых слов. Подсказка слова показывает вес.
4. **Параметры BM25**: `k1=1.5`, `b=0.75` по умолчанию. После изменения повторите поиск.
5. **Коллекция**: загрузка HTTP(S)-страницы или ручное добавление заголовка, URL и текста.
   Выбранные документы удаляются вместе с индексом и связанными оценками.
6. **Оценка качества**: задайте запрос и оцените каждый документ: 0 — нерелевантен,
   1 — частично полезен, 2 — релевантен. Обе положительные оценки считаются релевантными.
7. **Оценить запрос / Оценить все запросы** строит метрики и график.
8. **Отчёт и печать** открывает подробный HTML; **Скачать всё** сохраняет ZIP
   с параметрами, JSON, CSV, графиками SVG/PNG. История хранит отдельные запуски.

Веб-база — `webapp/work/search.sqlite3`; при первом запуске создаётся отдельная
копия прежней базы. Консоль по умолчанию использует `lab1/data/search.sqlite3`.
Изменение одного хранилища не синхронизирует другое автоматически.

## Загрузка страниц и ограничения

HTTP(S)-загрузчик извлекает заголовок и текст HTML, убирает script/style/head,
декодирует HTML-сущности. Поддерживается также text/plain. Редиректы учитываются.
Размер ответа — до 2 МиБ, таймаут сетевой операции — 15 секунд.

Повторная загрузка URL обновляет документ. Если текст изменён, индекс перестраивается
и оценки этого документа удаляются. Неизменённый текст сохраняет оценки.
Ручное добавление не скачивает указанный URL.

Поиск выполняется по сохранённой коллекции. Рекурсивного обхода сайтов,
исполнения JavaScript, авторизации, PDF-импорта и семантического поиска нет.

## Алгоритмы

Заголовок и текст приводятся к нижнему регистру, английские слова выделяются
регулярным выражением, фиксированные стоп-слова удаляются. Для документа считаются
частоты терминов; в запросе повторы исключаются. Стемминга и лемматизации нет:
`program` и `programming` — разные термины.

Ключевые слова: `tf(t,d) * ln(N / df(t))`. Для термина во всех документах вес равен нулю.

BM25 суммирует вклады найденных терминов:

```text
idf = ln(1 + (N - df + 0.5) / (df + 0.5))
вклад = idf * tf * (k1 + 1) / (tf + k1 * (1 - b + b * длина / средняя_длина))
```

В выдачу входят документы хотя бы с одним термином запроса. Балл не является
вероятностью или процентом. При равных баллах используется порядок ID документов.
`k1` управляет насыщением частоты, `b` — нормализацией по длине.

## Оценка качества

Разметка нужна для всей коллекции, чтобы учитывать пропущенные полезные документы.
Рассчитываются Precision, Recall, AP, P@5, P@10 и R-precision. AP делится на общее
число релевантных документов, включая пропущенные. P@5/P@10 всегда делятся на 5/10.
Запросы с R=0 исключаются из средних и перечисляются отдельно. Если исключены все,
система сообщает об ошибке. Метрики запросов усредняются арифметически; среднее AP — MAP.
Для TREC-кривой используются 11 порогов полноты от 0 до 1, недостигнутые пороги дают 0.
F1 и Accuracy как классификационные показатели в поисковый отчёт не входят.

[Методика оценки](docs/ROMIP_METRICS.md) · [Архитектура и карта файлов](docs/ARCHITECTURE.md)

Сохранённый [демо-отчёт](reports/demo/report.html) относится к исходным 12 документам
и пяти запросам. Это демонстрация на заданной разметке, а не независимая оценка качества.
Новые документы и пользовательские оценки меняют результаты.

## Консольные команды

Параметр `--db` задаётся перед подкомандой. Из корня проекта:

```powershell
.venv\Scripts\python.exe -B -m lab1 demo
.venv\Scripts\python.exe -B -m lab1 search "python programming" --limit 10
.venv\Scripts\python.exe -B -m lab1 fetch https://docs.python.org/3/library/pathlib.html
.venv\Scripts\python.exe -B -m lab1 --db lab1/data/search.sqlite3 evaluate --output lab1/reports/local
.venv\Scripts\python.exe -B -m lab1 evaluate --demo --output lab1/reports/verification
```

`evaluate --demo` использует изолированную коллекцию в памяти.

## Проверки

```powershell
.venv\Scripts\python.exe -B -m unittest discover -s lab1/tests -t . -v
.venv\Scripts\python.exe -m ruff check lab1
.venv\Scripts\python.exe -m ruff format lab1 --check
```

Проверяются BM25/TF-IDF и метрики по ручным примерам, нормализация, индексация,
обновление/удаление, транзакции, полнота разметки, экспорт, обработка HTML,
неизменяемые снимки, ошибки и направление зависимостей. Веб-API, конкурентный
доступ к коллекции и браузерные сценарии проверяются в `webapp/tests` и Playwright.
