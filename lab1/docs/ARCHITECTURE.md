# Архитектура первой лабораторной

Приложение разделено на вычислительное ядро, прикладные сценарии, адаптеры
и представление. Веб-интерфейс и консоль вызывают одни и те же сервисы.

```mermaid
flowchart TD
    Browser[React: Lab1.tsx] --> API[FastAPI и очередь webapp]
    API --> Adapter[webapp.experiments]
    CLI[presentation.cli] --> Bootstrap[bootstrap.application_runtime]
    Adapter --> Bootstrap
    Bootstrap --> Services[application.services]
    Services --> Domain[domain: текст, BM25, метрики]
    Bootstrap --> Infrastructure[SQLite, HTTP, экспорт]
    Infrastructure --> Domain
    Infrastructure --> Storage[(SQLite и файлы)]
```

| `ir_system/bootstrap.py` | Создание и соединение реализаций, закрытие базы |

| `domain/text.py` | Токенизация, частоты, уникальные термины запроса, проверки |

| `application/services.py` | Коллекция, поиск, экспертная разметка, оценка и экспорт |

## Путь поиска

Кнопка отправляет action/query/k1/b. Сервер ставит опыт в очередь и вызывает
`SearchService.search`. Анализатор выделяет уникальные термины, репозиторий
создаёт согласованный `CorpusSnapshot`, ранжировщик возвращает `SearchResult`.
Веб-слой сохраняет JSON и состояние опыта. Браузер получает результат опросом API.

## Хранение

Таблицы `documents`, `postings`, `queries`, `judgments` хранят тексты, инвертированный
индекс и оценки для пар запрос/документ. Внешние ключи и каскадное удаление включены.
Добавление и индексирование, импорт демо и групповые изменения атомарны.
Вложенные транзакции используют SAVEPOINT. Изменение текста аннулирует прежние оценки.

Веб-версия использует `webapp/work/search.sqlite3`, консоль — базу из AppConfig.
При первом запуске веба существующая база копируется через SQLite backup.
Соединения создаются в вызывающем потоке и закрываются context manager.
Веб-адаптер сериализует обращения к коллекции через RLock, поскольку репозиторий
проверяет и инициализирует схему при открытии каждого соединения.

## Зависимости и проверки

`domain` не импортирует представление, хранилище или графические библиотеки.
`application` обращается к инфраструктуре через Protocol-контракты.
Bootstrap явно передаёт реализации; глобального репозитория и соединений между потоками нет.

Тесты проверяют предметные расчёты, транзакции, сохранность отчёта при ошибке,
архитектурные границы, CLI и фиксированный демо-эталон. Общие веб-тесты проверяют
очередь, конкурентные чтения/записи, историю, файлы и реальные браузерные сценарии.
