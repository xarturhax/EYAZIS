# Лабораторная работа №4 · Вариант 12

Локальный перевод **английский → французский** для медицинских текстов
и художественной критики. Полный перевод выполняет Marian/OPUS-MT,
грамматический анализ и дерево зависимостей — spaCy.

## Запуск

Из корня проекта в PowerShell:

```powershell
.venv\Scripts\python.exe -m pip install -r lab4\requirements.txt
.venv\Scripts\python.exe -B -m lab4.tools.download_model
.venv\Scripts\python.exe -B -m lab4
```

**В текущем окружении зависимости и модель уже установлены.**
Повторная загрузка для обычного запуска не нужна.
Модель хранится в `lab4/models/opus-mt-en-fr`, загрузчик проверяет HTTPS
и записывает SHA-256 файлов. Веса около 301 МБ, ревизия закреплена в коде.
При переводе сеть не используется. Выполняется на CPU, 2 потока, beam search=4.

Работают также прямой запуск `lab4/main.py` из корня и `main.py` из папки lab4.
В интерфейсе нажмите **Демо: медицина / искусство → Перевести**.
Демо-кнопки используют короткие оригинальные учебные тексты.
Фрагменты реальных источников можно открыть из `lab4/data/demo/source_*.txt`.

## Что доступно

- Ввод, вставка и открытие UTF-8 TXT; выбор medicine / art.
- Полный перевод с сохранением абзацев.
- **Вкладка 1:** словарь по убыванию частоты, леммы, переводы, части речи
  и их расшифровки, Penn Treebank-теги и их пояснения, словоформы и морфология.
- **Вкладка 2:** настоящее дерево зависимостей выбранного английского предложения.
- Ручная корректировка словаря двойным щелчком или кнопкой «Исправить эквивалент».
- «Автопополнение» обновляет автоматические эквиваленты, сохраняя ручные правки.
- «Сбросить правку» удаляет выбранный эквивалент; автопополнение восстановит его.
- Сохранение перевода и словаря в **Unicode TXT (UTF-8 с BOM)**, JSON, CSV,
  дерева в SVG и всего отчёта в HTML.
- Печать / сохранение PDF через кнопку в HTML; справка F1.
- Фоновая обработка и отмена между предложениями и группами слов.
  Текущая генерация завершается перед отменой.

Изменение текста или области сбрасывает устаревший результат.
Ручные эквиваленты хранятся в SQLite между запусками.
Правка словаря не подменяет слова в нейронном переводе всего текста.

## Подсчёт слов и статусы

Исходное слово — токен spaCy, содержащий хотя бы одну букву.
Знаки и чистые числа не учитываются. Апострофные конструкции spaCy может
делить на части: `viewer's` учитывается как `viewer` и `'s`.

**Переведённые исходные слова** — число вхождений, покрытых словарём:
эквивалент непустой и либо отличается от исходной леммы, либо подтверждён вручную.
Это операционная оценка покрытия, **не точность** и не выравнивание слов
исходного и французского текстов.

В экспортированном словаре:

- `covered`: эквивалент участвует в покрытии;
- `review`: автоперевод совпадает с английской леммой, требуется проверка;
- `missing`: эквивалента нет.

`patient` и `composition` могут корректно совпадать в EN/FR, поэтому статус
review сам по себе не означает ошибку. Сохраните проверенный эквивалент вручную,
даже без изменения строки: запись станет manual и войдёт в покрытие.
Число французских слов показано отдельно; считается Unicode-выражением
с сохранением внутренних апострофов и дефисов.

Автоматические словарные переводы получены **для отдельных лемм**.
Они могут ошибаться из-за отсутствия контекста: проверяйте их.
Ключ словаря — лемма + POS + область + ревизия модели.
Выбор области разделяет словари; сама модель отдельно по областям не обучалась.
Частоты вычисляются заново для текущего текста и не накапливаются в БД.

## Консоль и отчёты

```powershell
.venv\Scripts\python.exe -B -m lab4 translate --input lab4\data\demo\source_medicine.txt --domain medicine --output lab4\reports\custom
.venv\Scripts\python.exe -B -m lab4 translate --input lab4\data\demo\source_art.txt --domain art --sentence 2 --output lab4\reports\custom_art
```

`--sentence` выбирает дерево по номеру от 1.
`--database` задаёт отдельный SQLite-файл; по умолчанию `lab4/data/lexicon.sqlite3`.
Для подготовленных источников CLI переносит атрибуцию из соседнего provenance.json
в отчёт. При самостоятельном распространении своего текста указывайте его источник.

[Готовые примеры](reports/demo/index.html) · [Описание для защиты](docs/REPORT.md)

В каждой папке отчёта: translation.txt, dictionary.txt, dictionary.csv,
results.json, tree.svg, report.html. TXT содержит полный исходник/перевод
и частотный список с грамматикой. HTML отображает те же данные и вызывает
диалог печати. Физический принтер не проверялся.

## Ограничения и воспроизводимость

До 50 000 символов за один запуск, входной файл до 1 МиБ.
Предложения длиннее 384 токенов модели разбиваются на части:
токены не обрезаются, но на границах может теряться контекст.
При достижении лимита генерации без EOS приложение выдаёт ошибку,
вместо сохранения частичного перевода.
Качество на художественных оборотах и специальных терминах требует проверки.

Для точной установки Windows/Python 3.12 сохранён `requirements-lock.txt`
(66 runtime-дистрибутивов). Модель скачивается отдельно, её ревизия и хеши
записаны в models/opus-mt-en-fr/revision.json.

```powershell
.venv\Scripts\python.exe -m pip install -r lab4\requirements-dev.txt
.venv\Scripts\python.exe -B -m unittest discover -s lab4/tests -t . -v
.venv\Scripts\python.exe -B -m lab4.tests.gui_smoke
.venv\Scripts\python.exe -m ruff check lab4 --no-cache
.venv\Scripts\python.exe -m ruff format lab4 --check
.venv\Scripts\python.exe -B -m mypy lab4 --config-file lab4/pyproject.toml --no-incremental
```

Пересобрать реальные примеры из сохранённого корпуса lab3:
`python -B -m lab4.tools.build_demo`.
Сформировать все четыре отчёта с чистым временным словарём:
`python -B -m lab4.tools.build_reports`.
Модели загружаются один раз на такой пакетный запуск.

Повторно используется общий TaskRunner из `lab2/presentation/tasks.py`:
для запуска GUI сохраняйте структуру всего репозитория.
Адаптация весенних работ описана в REPORT.md; исходники весенних работ не изменены.
Журнал ошибок с ротацией: `lab4/logs/lab4.log`.
